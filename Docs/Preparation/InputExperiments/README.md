# T04/T05 输入平台实验准备稿

**状态：计划/模板，所有案例 `NOT_RUN`。** 本目录不代表Unity/Udon、Station、Jump拦截、A/B/PC输入等已实现或已可用；不冻结任何公共接口或实际绑定。

## 范围与依据

按当前项目方向准备PCVR A、PCVR B与Desktop平台实验。A为胸前固定轮廓归中参考件+可抓取活动件，局部水平面限位、用户可调；B以摇杆输入球路径并稳定追尾；Desktop采用对应二维运动意图。所有设备输入最终意图应由同一球运动模型处理，硬件差异/原生转向设置必须实测。Quest不属于首版目标。

建议证据：范围决策、技术契约、玩法与体验、验收测试、P03离线矩阵、P05术语/教学准备。它们是设计要求，不是已验证实现。记录字段见 [cases.csv](cases.csv)，真人安全边界见 [human_safety.md](human_safety.md)。

## 开测前必须记录

- `run_id`、case ID、测试日期/时区、构建提交或哈希、Unity/VRCSDK/UdonSharp精确版本；任一未知就写`unknown`，不能猜。
- 设备：PC/VR模式、头显型号/刷新率、左右控制器、原生转向设置、跟踪方式、控制绑定版本；没有使用的平台写`N/A`。
- 参数：模式A归中位置/间距/水平行程/死区/灵敏度/回中设置，或B/PC绑定与转向选项；保留本次配置快照标识，不预设通过值。
- 环境与玩法：场景/回合、玩家生命状态、当前持有道具、是否在Station、网络参与者数；仅按该案例所需填写。
- 参与者代码（匿名编号即可）、自愿同意/中止确认；不记姓名、账号或无关健康信息。
- 测试人/观察人，复现步骤，预期与实际分开，失败次数，截图/日志相对路径，未知项与偏差。
- 入场前的可恢复玩家设置快照、实际保存方式及恢复责任人/组件（`restore_owner`）；只列工程实际可访问/可恢复的设置，不能假设API存在。检查每条退出路径恢复身高/移动/跳跃相关设置、Station与输入状态，不覆盖玩家原有偏好。

## 统一测试原则

1. 先做非真人输入/状态检查，再做短时、低风险真人测试；一次只改变一个平台或设置变量。测试前确保可以安全退出，监测者不强迫连续完成。
2. 设置死区/行程/角度阈值之前，先由主管和用户依据输入设备与实际手感确定；本模板不定义合格容差、帧率或舒适阈值。
3. 对输入建立可观测记录：原始输入（如实现可见）、模式转换后意图、球移动结果、道具激活次数、Station状态、设置快照差异。不得凭画面猜输入API可用。
4. Jump只按当前契约作为比赛内“使用当前道具”的建议动作，测试上升沿单次触发、持续按住不重复；验证是否意外触发默认跳跃/退出Station。监听输入不等于拦截动作，失败则记阻塞/不支持，不换成未经批准的特殊键。
5. 对比A/B/Desktop的同一运动意图和统一速度/加速度上限，不要求物理动作逐帧相同；输入方式不得使挥手/键盘满轴成为额外无限增益。确切等效标准由主管/测试者先定。
6. KO、模式切换、菜单/追踪丢失、主动退出、回合结束和平台Respawn分别运行清理用例。KO不是主动退出；只在真正的离赛/复位事件中从参赛流程离开。验证输入清零和设置恢复责任清晰、无残留。
