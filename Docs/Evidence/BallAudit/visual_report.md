## 1. 现状：视觉球、物理球、吸附位置、长大后的吞没

### 1.1 三个半径

**(代码)**
- 物理核心半径 `coreRadiusWorldM`：`SizeModelMath.TryDerive`（`Runtime/BallLayers/SizeModel/SizeModelMath.cs:126`–`192`），
  `core = min(cbrt(3(baseline+confirmed)c/4π), 1.1)`。
- 碰撞半径 `collisionRadius = core × collisionToCoreRadiusRatio`；语义直径 `= 2·core × semanticDiameterPerCoreDiameter`。
  序列化值 **两个比例都 = 1**（`Runtime/BallMotor/KatamariBallMotor.cs:193`–`197`；场景 `PhysicsTestField.unity:8813`–`8814`）。
- 视觉网格：`BallView.Update()` → `coreMesh.localScale = Vector3.one * motor.GetSemanticDiameterWorldM()`
  （`Runtime/BallPresentation/BallView.cs:44`–`62`），注释明写"只缩放 coreMesh，绝不缩放 attachment root"。
  ⇒ **今天视觉球半径 = 物理 core 半径 = 碰撞半径**，三者同一个球；`D=2·r`。

### 1.2 吸附瞬间道具被放在哪里

**(代码)** `PickupFieldHost.AttachProp`（`Runtime/Pickup/PickupFieldHost.cs:976`）：
- 取道具**当时的世界位姿** `prop.position/rotation/lossyScale`（`:991`–`993`）；
- 用 `AttachmentMath.TryWorldPoseToLocal(ballCenter, visualRollRotation, …)`（`Runtime/BallLayers/Attachment/AttachmentMath.cs:95`）算球局部位姿；
- `prop.SetParent(attachmentRoot)` 后写 `localPosition/localRotation`（`PickupFieldHost.cs:1013`–`1015`），**不写 localScale**；
- 同时 `motor.AttachRadialProxy(itemId, …, localPosition, localRotation)`（`:1025`）。

**没有任何"贴到球面"的步骤**：道具停在被吸收那一刻的位置。允许范围由吸收门决定：
`reach = collisionRadius + contactRadius(0) + itemRadius`，`itemRadius = AABB 半对角线`
（`Runtime/Pickup/PickupAbsorbMath.cs:244`–`266`），判据是**球心到道具中心**的距离（`:228`）。
所以：
- **不是接触面**，是 **reach 内的任意位置**；
- 上界 `d ≤ r + ½·diag(AABB)`：对一个 0.15 m 的立方体，`itemRadius = 0.13`，`d ≤ r + 0.13`，
  比"面贴面"（`r + 0.075`）远 5.5 cm；
- 下界：吸收门每固定步评估一次，但宿主 20 Hz 扫描（`scanIntervalSeconds = 0.05`，场景值），
  球最快 4 m/s ⇒ 从"进入 reach"到"真的提交并评估"最多再走 **0.05 s × 4 = 0.20 m**，
  这 0.2 m 可能全落在道具上 ⇒ **道具可以在中心已经进入球体内部之后才被吸**（D=0.30 时 reach 才 0.17–0.20 m）。

**(测量)** 我们的截图（`ours_unity_ball_with_props.png`）里 5–6 件可见道具中有 3 件明显被红球切掉一部分：
左侧黑箱约 **40–50%** 体积在球面以内、右侧长凳约 **30–40%**、底部木板只露出边缘（**≈70–80% 被吞**）。
（看像素估的，误差 ±15 个百分点。）

### 1.3 长大后道具的局部位置是否变

**(代码)** 变不了：道具是 `attachmentRoot` 的子节点，`BallView` 只改 `coreMesh`，马达 `ApplyPresentation()`
只写 `ballPhysicsRoot.position` 与 `ballVisualRollRoot.rotation`（`KatamariBallMotor.cs:1774`–`1783`），
**没有任何代码按新半径重投影已吸附道具**（grep `localPosition` 只有 attach / reset 两处）。
⇒ 球长大后 core 半径变大、道具不动 ⇒ 早先的道具被吞。

### 1.4 数值例子（题目给的）

D=0.5 时吸一个 0.15 m 的物体，中心距 `d = 0.25 + 0.075 = 0.325`（面贴面）。

| 球长到 | 半径 | 道具中心距 | 中心在球面下 | 外表面在球面下 | 状态 |
|---|---|---|---|---|---|
| D=0.6 | 0.30 | 0.325 | **−0.025（还在外面）** | −0.10 | 露出 |
| D=0.8 | 0.40 | 0.325 | +0.075 | **0.000（刚好全埋）** | **全埋** |
| D=1.0 | 0.50 | 0.325 | **+0.175** | **+0.100** | 全埋 0.10 m |

**全埋阈值：`r' ≥ d + h = r + 2h`，即 `D' ≥ D + 4h`。** 即球径再长 **4×道具半长** 就完全吞掉它。
- 现行定价（中位 **+11.6% 直径/件**）：`0.5 → 0.8` 只需 **≈4 件** ⇒ 一口吞下的东西 3–4 件后就不见了。
- 重定价后（中位 **+0.81% 直径/件**）：同样过程要 **≈50 件**。
  这条式子就是"半埋"的根因，与视觉半径无关。

## 2. 离线模拟

### 2.1 方法（`/tmp/ball_audit/cover_sim.py`）

- 127 件真实道具（`aabb`、`absorbDiameterReq` = 体积门解出的直径、`valueUnits`），
  球从 `ballStart` 起，按"当前能吸的里面最先/最大/就近"逐件吸收；
  每件按"贴着当时球面"放置（`d = r + 支撑函数`），朝向随机（球滚过去，球局部朝向随机），
  之后按方案决定是否随球长大外推。
- 生长：现行（`c=0.0041 m³/u`、`baseline=3.439`、价值用 `valueUnits`）；
  重定价（`c=0.0005`、`baseline=28.2`、价值 = `max(1, round(V/0.0005))`）。
- **两个度量**（每 5 件一测）：
  - **M1 表面覆盖**：视觉球表面上 3000 个 Fibonacci 采样点，落在任何已吸附道具 OBB 内的比例（题目字面要求）。
  - **M2 红色可见**：视觉球圆盘内逐像素**射线**求交，看"第一个命中是球本体的比例"；
    被埋在球体内部的道具**不算遮挡**（它在球面后面）。这是"还能看到多少红"的度量。
  - 埋没深度：`r − d`（中心，正=在球面下）、"全埋"= `d + max半边长 < r`。
- 12 个视角、56×56 网格、固定种子（可复现）。合成校验：20 个 0.2 m 方块贴在 r=0.25 球上 →
  模拟 48.5% 可见（解析估计 ~40–50%），量级正确。

### 2.3 哪个方案能把 20–30 件时的可见比例压到 <10%

**没有一个。** 最好的组合（重定价 + k=0.6 + 外推 + 贴视觉面）在 30 件时是 **42%**，
继续吃到 60 件也还有 **33%**。原因不是视觉半径：**是"道具尺寸/球尺寸"这个比值**。

- 视觉半径 k 只按 `1/k²` 放大"道具投影面积 / 球投影面积"，本关最多把 71% → 53%（A 表），
  因为道具本身就小：D=1.86 时场里最大的几件才 1.2–1.6 m，其余 0.1–0.5 m。
- 外推 (c) 只修"埋"，**不修"红"**：它把 30 件全埋率从 30–60% 降到 0，可见比例只动 ±2 点
  （甚至变差：b/c/d 里道具被推到离小球更远的物理面，投影落到圆盘外）。
- 真正的大杠杆是 **(e) 重定价**：同样 30 件，球从 1.04–1.86 m 降到 0.40–0.50 m，
  可见红从 86%/71% 降到 70%/50%。
- 要真正到 <10%，道具的第一维（投影半宽）得 ≈ **0.5–0.7 × 球径**：
  按本关数据，20–30 件需要平均尺寸 **≈0.4–0.5 m**、且球径停在 **0.6–0.8 m**。
  这正是原作截图里的比例（见 §3）。

> 结论一句话：**"20–30 件就看不到球"不是视觉层的参数能买到的，它是"内容尺寸 × 生长速度"的函数。**
> 视觉半径只能买到 ~1.4× 的改善；生长定价能买到 ~2×；两者叠加 ~2.5×，仍到不了 10%。

## 3. 原作怎么做：证据 vs 推断 + 三张图的测量

### 3.1 专利里的（证据）

`[专利]` = US7402104B2 正文，`/tmp/orig_physics/report.md` §2.2/§4.2：
1. **三个模型分离**：显示 `Mp` / 碰撞 `Mh` / 滚动 `Mr`（P3）。
2. **碰撞 `Mh` = 包围盒，内含一个"体积 = 球体积 + 所有已吸附物体积之和"的等效球**，吸附后按体积增量整体放大（P3）。
3. **滚动 `Mr` = 16 根固定针 + 4 根可选针，针尖是接地点**；吸附物把附近的针**伸长**（P4）——
   这套只影响接地/滚动，不进碰撞。
4. **显示 = 父子层级，吸附瞬间记录位置+姿态，保持原尺寸**（P5/P8）——**没有任何"径向外推"**。
5. **小物件按 display level 不画**（P5）——"比球小得多的不显示"。
6. 拾取门 = 物件自己的碰撞盒 + 10% 体积比（P3 段）。

`[社区实测]`（同一份报告 §4.2 D3–D6）：日文 wiki"尺寸小的物件球一大就消失"；5ch"吸进去的东西消失、露出块底"；
新作被批"物件 30 秒内大量消失、只剩十几个"。⇒ **原作也埋/也消隐**，只是它保留得久。

### 3.2 三张图的测量（**推断**，视觉估计）

| 量 | 原作 14.0 cm / 14.9 cm | 我们（截图） |
|---|---|---|
| HUD 球径 | 14.0 / 14.9 cm（画面左上角，直接读数 = 语义直径） | 无 HUD；红球直径 ≈230 px |
| 粘附簇外径 / HUD 球径 | **≈2.3–3.0**（见下） | 簇/球 ≈1.2–1.4（只有 5–6 件可见） |
| 单件尺寸 / 球径 | **≈0.4–0.7**（牛奶盒高约 0.68D、蜜柑约 0.4D、纸屏/筷套更长） | **≈0.5–0.9**（黑箱 0.5、长凳 0.65、木板 0.9）但**件数只有 5–6 可见** |
| 球本体可见 | **几乎 0**（簇把整圈撑满） | **≈60–80%** 的红 |
| 被红浸没的深度 | 看不清（没有露出的核） | 单件 **30–80%** 体积在球面内 |

**簇外径/HUD 球径的估法与误差**：两张原作图里取两个"已知真实尺寸"的参照——
200 ml 牛奶盒高 ≈9.5 cm（图中 ≈130 px ⇒ 13.7 px/cm）、蜜柑直径 ≈6 cm（≈100 px ⇒ 16.7 px/cm），
簇的像素包围盒 ≈560–570 px ⇒ **34–41 cm**；除以 14.0/14.9 cm ⇒ **2.3–2.9**。
误差来源：透视（参照物与簇不同深度）、牛奶盒/蜜柑真实尺寸的不确定、簇边界被长条物撑开。
**取 2.5，误差 ±0.4（±16%）。**

**读法（推断）**：簇半径 ≈ 1.25×球半径，说明粘附物**向外**伸到 `r + 0.25r` 以上，而球本体的半径（HUD）
只是簇的 0.35–0.45 ——**也就是说"看到的核"比"物理球"小**，或者核被完全遮住。
结合专利（碰撞体积 = 球 + 所有物件体积、显示层记录冻结位姿、小件 cull），我的最佳推断是：

> **原作的可视核 = "裸球"体积对应的半径，比碰撞等效球小 `(1 + ΣV_item/V_ball)^(-1/3)`；
> 吸附物不径向外推，只按 display level 消隐。** 20–30 件、每件 0.4–0.7 D 时，
> 1) 簇自身就把核遮住；2) 早先被埋的小件被 cull 掉，不会出现"半埋"的丑状。
> 置信度：**中（0.55）**"可视核 < 碰撞球"；**低–中（0.4）**"可视核 ≈ 0.6–0.75 碰撞球"这个具体比例；
> **高（0.8）**"不会比碰撞球更大"；**很低（<0.2）**"原作会按半径比例把已吸附物往外推"（专利明确是冻结位姿）。

## 4. 推荐方案与最小实现位置

### 4.1 不要动的东西

- **不要改 `semanticDiameterPerCoreDiameter`**。它同时进：吸收门的 `π/6·D³`（`PickupAbsorbMath.cs:348`）、
  HUD（`GetSemanticDiameterWorldM`）、相机视高（`FollowRig`）、`stepLimit = 0.25D`（`SupportSurfaceMath.cs:188`）、
  以及 `BallView` 的网格缩放。改成 0.7 会**同时**让吸收门、台阶、相机全部错位。
- **不要把视觉缩放写到 `ballVisualRollRoot` / `ballPhysicsRoot`**：`attachmentRoot` 是它们的子节点
  （`Worlds/StoryMode/StoryMode.unity` 里核实：`PlayerBall → BallPhysicsRoot → BallVisualRollRoot → {CoreMesh, AttachmentRoot}`），
  写到父节点会把已吸附道具一起放大（这是现在**没有**发生的、也必须保持的）。

### 4.2 推荐：三层，按顺序做

**(R1) 先改生长定价（(e)）——收益最大、风险最低。**
`KatamariBallMotor.cubicMetersPerVolumeUnit 0.0041 → 0.0005`、`baselineVolumeUnits 3.4390244 → 28.2`、
`maxCoreRadiusWorldM 1.1 → 0.85`，价值表按 `valueUnits = max(1, round(V_box/0.0005))` 重导。
效果（模拟）：30 件时 D 从 1.04–1.86 → 0.40–0.50，红从 86%/71% → 70%/50%；全埋率 60% → 7%。

**(R2) 新增"只作用于 coreMesh"的表现系数（不要复用语义比例）。**
在 `BallView` 加一个序列化字段 `visualCoreScale = 0.7f`，只改一行：
`coreMesh.localScale = Vector3.one * (semanticDiameterM * visualCoreScale);`（`BallView.cs:61`）。
代价与副作用（必须一起做）：
- 物理球仍是 `r`，视觉球变成 `k·r` ⇒ 球会**看起来离地** `(1−k)·r`。
  补偿：在 `BallView` 里把 `coreMesh.localPosition` 沿世界 −Y 下移 `(1−k)·r`
  （`coreMesh` 的父节点会随视觉滚转旋转，所以下移必须写在**不旋转**的 `ballPhysicsRoot` 上，
  或给 `coreMesh` 一个专门的"非滚转"父节点）——这是唯一需要新节点/新写法的点。
- 吸附道具的"贴面"位置若仍用物理 `r`，会浮在视觉球外面 `(1−k)r`；
  所以 (R3) 必须同时做，否则会更难看。
- 收益（模拟）：k=0.6–0.7 在 30 件时再降 8–15 个百分点。

**(R3) 吸附时的"贴视觉面"内插 + 生长时的径向外推（(f)，而不是 (b)/(c)）。**
- 位置：`PickupFieldHost.AttachProp`（`PickupFieldHost.cs:1005`–`1026`）是唯一同时拥有
  "球位姿 / 道具位姿 / attachmentRoot / 径向代理登记"的地方，**就在这里做**：
  算出球局部位置后，把它的**径向分量**改成 `k·r + h_radial`（道具内表面贴视觉球面），
  再写 `prop.localPosition`、再调 `motor.AttachRadialProxy(…, 改过的局部位置, …)`。
  **先改位置、再登记代理** ⇒ 视觉与代理壳仍然一致（代理只影响接地高度，端点必须跟着走）。
- 生长外推：球每长一点就把所有道具的径向分量重设为 `k·r_now + h_radial`（保持朝向、不改 scale）。
  放置点：`PickupFieldHost` 的 Update 里，跟着 `motor.GetSemanticDiameterWorldM()` 变化做（阈值 1 mm），
  同一次里对**已登记代理的 ≤4 件**重新 `AttachRadialProxy`（或先 `Detach` 再 `Attach`），保证代理壳同步。
- 为什么不做 (c) 的"绝对深度不变"而做"贴视觉面"：模拟里 (c)/(d) 让道具离小球更远、红反而变多（§2.2）。
- 远端一致性：这些全是**表现层**，物理半径没变 ⇒ 远端同步的球心/半径不动；
  但如果远端也画道具（`RemoteProxyMath` 有 `visible/buried` 槽位），`buried` 的判定应改成
  "在**视觉**球内"（`k·r`），否则两端消隐阈值不一致。

**(R4) 显示层消隐（照抄原作，最便宜的一条）。**
道具一旦 `d + max半边长 < k·r`（完全在视觉球内）就不再需要绘制；
按原作再加一条"最大边 < 0.15·D 就不画"。这不是可选项：现状 30 件有 **30–60% 全埋**，
既看不见又占 draw call。放在 `PickupFieldHost`（它已经管 `propStates`/`HideProp`，`PickupFieldHost.cs:1059`）。

## 5. 结论（≤30 行）

1. **今天只有一个球**：视觉网格按 `semanticDiameter` 缩放，`semanticDiameter = 2·core = 2·collision`（两个比例都 1）。
   视觉球、滚动球、挡墙球、吸收 reach 球**完全同一个球**。
2. **吸附不是"贴面"**：`AttachProp` 用吸收瞬间的世界位姿，`attachmentRoot` 下保持球局部位置；
   允许范围是 `reach = r + AABB 半对角线`（球心到道具中心），且 20 Hz 扫描 + 4 m/s 允许再深入 0.2 m
   ⇒ 道具可以在**中心已经进入球体**时才被吸；之后位置**永不更新**。
3. **吞没有解析阈值**：`D' ≥ D + 4h` 就全埋。D=0.5 吸 0.15 m 物件，D=0.8 全埋，D=1.0 时中心在面下 **0.175 m**、
   外表面在面下 **0.10 m**。现行定价 **≈4 件**就到；重定价 **≈50 件**。
4. **模拟（127 件真实数据、12 视角射线遮挡）**：现状 30 件时红 **71%（最大先吃）/ 86%（就近）**，
   全埋 30%/60%。`k=0.6` 视觉球：53%/76%。径向外推：埋没归 0，但红只降 0–3 点（甚至会变差）。
   重定价：50%/70%。重定价+k0.6+贴面：**42%/57%**。
5. **<10% 在 20–30 件时达不到**：吃到 60 件也只收敛到 33–46%。瓶颈是**道具尺寸/球径**（本关 0.05–0.25D），
   不是视觉半径。要 10% 需要平均件 ≈0.4–0.5 m 且球停在 0.6–0.8 m。
6. **原作对照**：HUD 14 cm，簇外径/HUD ≈ **2.5（±0.4，方法见 §3.2）**；单件 **0.4–0.7 D**。
   专利证据：碰撞 = 等体积球（含吸附物）、滚动 = 16+4 针、显示 = 冻结位姿 + 小件 cull，**没有外推**。
   推断（中置信 0.55）：原作的可视核是"裸球"，比碰撞球小；"看不到红"靠的是**件大 + 件多 + cull**，
   不是靠"把球缩小"。
7. **推荐**：R1 重定价（最大杠杆）→ R2 `BallView` 加**只作用于 coreMesh** 的 `visualCoreScale≈0.7`
   （**不要**动 `semanticDiameterPerCoreDiameter`）→ R3 吸附时径向贴到 `k·r`、生长时随动并同步代理
   → R4 视觉球内消隐 → R5 每档补薄长件。
8. **明确不要**：把视觉缩放写到 `ballVisualRollRoot`（会放大已吸附道具）；只做 (b) 或只做 (c)
   （一个让道具浮空、一个只治埋不治红）。
