# P09 规则与项目选择决策矩阵

**盘点日期：2026-10-11。** 本文区分可复核官方文字、公开资料未说明的 `unknown`、当前项目范围选择、待确认的项目原型参数。它不是T01最终验收、用户批准记录、原作完整规则、实现证据或T06接口冻结；不得从项目建议推断原作机制。

## 文件与证据层级

- [decisions.json](decisions.json)：每个主题分别记录已确认内容、unknown、项目选择/原型、候选选项及选择风险。
- 官方文字依据为 [T01参考规则矩阵](../../Research/ReferenceRules/rules_matrix.md) 所引Bandai Namco Europe FAQ（S02）和公告（S03）。仅采用其明确表述，不把宣传用语外推到具体PVP流程。
- 当前项目决定以 [00范围与事实边界](../../00_SCOPE_DECISIONS.md)、[02技术契约](../../02_TECHNICAL_CONTRACTS.md)、[01玩法草案](../../01_GAME_DESIGN.md) 为准；任务状态和依赖以仓库根 `tasks.json` 为准。
- 可选项是供用户/主管评估的候选，不是投票结果。`recommended_option`保持空值，`decision_owner`列为用户/主管或之后相应门禁负责者。

## 如何使用

1. 发布/冻结任何原作规则前，先看 evidence_status。只有官方文本明示的有限事实属于 `official_text_confirmed`；公开文档未回答即 `unknown`，不能用经验、旧作或AI推断补齐。
2. 对 unknown，可先按项目已明确方向构建可调方案；若项目规格尚未由用户/主管选择，维持待定，不将候选数值硬编码。
3. 每一选择列出单位与证据边界：几何长度用共享世界米，分数/收益使用各自账本单位，时间用秒；无已知值时写`unknown`，不填零或伪装实测。
4. 任何需参考游戏实机的新结论，需要获准、可复核的版本/模式/步骤/录像时间点。任何项目体验阈值需先由用户/主管确定，然后用对应真人/多人门禁验证。
5. 项目首发目标仍是两图；一图方案只是待批准的范围变更，见 [P17 RFC比较](../ReleaseRFC/comparison.md)。本目录不修改根任务或任务状态。

## 关键未决

T01已确认的只是新版KatamariBall为4人对战方向，限时滚大并兑换积分、最高积分获胜；具体时长、计分、交分、吞噬、KO/重生和PVP道具投放仍unknown。项目已有的被吞/重生、单槽磁铁/火箭、积分交存等是项目设计方向，不是对原作细节的认证。详见JSON并在接口冻结前由主管审阅。
