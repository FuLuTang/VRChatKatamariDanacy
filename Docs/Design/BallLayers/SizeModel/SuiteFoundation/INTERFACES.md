# B 套接口边界（DRAFT / 未冻结）

本文件仅为 T51 附着记录与 T52 尺寸纯函数的最小交接约定，供离线原型和独立 oracle 测试使用；不是跨模块正式 API，也不替其他套规定实现。公共接口仍待 T06。不得据此删除现有兼容测试。

## 责任边界

- **T51 附着记录**消费调用端已确认的拾取/附着事实及稳定身份，记录物件相对球刚体根的局部位姿和独立物件尺度。提供查询、幂等应用、撤销/移除和按局/快照重建所需的最小语义。它不作吸附资格判断、不裁决比赛、不累计收益、不计算尺寸，也不拥有Renderer预算、显隐、回收或装饰重建；这些视觉预算与回收由 T56 负责。
- **T52 尺寸映射**只读确认体积/尺寸参数并计算输出尺寸。它不记账、不决定收益、不更改账本、不读取附着数量/Mesh，也不限制碰撞规则。上限是呈现/尺寸映射政策，不能截断、归零或覆盖权威确认体积或得分。
- 输入事实的权威来源、确认事件格式和稳定序号由上游/正式契约定义。本套消费其身份，不擅自生成一个看似权威的本地递增序号。

## 最小身份语义（草案）

- 附着记录至少关联稳定球/对局上下文、物件实例身份、物件世代以及确认附着身份。若上游提供权威单调 `attachSequence`，原样消费；若上游提供确认事件 ID，则以该 ID（连同其定义的作用域）幂等消费。二者对应规则须在冻结契约时明确，不能本地“补号”冒充权威序号。
- identity 必须区分同一物件跨世代、跨局及同局多次有效事件；哈希仅是确定性键，不是身份认证或安全证明。不同事件不得因默认值/截断/字符串拼接碰撞而合并。
- 相同事件重放应无副作用且返回既有结果；同身份但负载冲突（例如同一确认 ID 携带不同位姿/物件键）应拒绝并报告冲突，不静默覆盖。
- 撤销指向精确身份/修订，不能误删新世代；对已撤销事件重放不得复活旧记录。新对局开始时按明确局身份隔离/清理临时态；快照重建是以完整快照原子替换相应作用域，不把不同版本分块混拼。
- 是否持久化、序号宽度、快照编码与并发写入者仍待正式契约；本层不得假设授权/排序语义之外的网络属性。
- 事件幂等/撤销身份（含context与event ID）与远端代理键为两种不同编码。候选远端键函数仅接受§3.4四字段 `ballSeed + instanceId + generation + attachSequence`；文本字段按UTF-8长度前缀、整数按固定宽度编码。`ballSeed`应由调用方显式传入；当前草稿假设规范非空文本，来源/值语义及最终类型仍OPEN，须由Lead/上游批准；若采用非文本seed，需先定义canonical编码。不能把round/context/ball/event ID冒充seed。SHA-256只提供确定性摘要，不是认证或绝对无碰撞保证；本说明不改写项目技术契约。

## 坐标、单位、姿态

- 采用项目共享坐标约定：世界 **Y 向上、+Z 向前**；长度单位米。位置 `Vector3` 各分量均为 world m 或明确标记为球局部 m，不可混用。附着根是球的刚体/运动根，而非随成长放大的球芯网格。
- 四元数采用 **xyzw** 顺序（`x,y,z,w`），表示旋转；需要矩阵适配时按同一右手旋转语义映射，必须明确行/列向量、矩阵存储次序和乘法方向，禁止仅因 API 默认值假设转置/顺序一致。具体 Unity 矩阵构造留给实现层验证。
- 世界转局部刚体变换草案：`localPosition = inverse(ballRotation) * (objectPosition - ballPosition)`；`localRotation = inverse(ballRotation) * objectRotation`。反向重建用球姿态与该局部位姿组合。该简化不覆盖带非均匀缩放/剪切的父级层级；遇到此条件应拒绝或由适配器先化为明确刚体坐标，而非悄然产生错误姿态。
- 物件自身 scale 单独记录并不乘球芯成长比例；不得将球芯半径、碰撞半径、直径或 semanticDiameter 填进同一字段。
- 尺寸模型输入体积单位和比例必须由调用者/参数明确提供；世界米不意味着确认体积单位就是 m³。所有参数是正有限数；确认增量按该函数约定为非负有限数。基线和参数冲突（例如半径上限小于基线所需半径）必须报错。

## 数值合法性、原子性与错误

- 接受运算前验证类型、身份必填字段、数值有限性及范围；布尔值不可伪装成整数/数值，整数必须满足范围/编码宽度。位姿、scale、参数及确认量含 NaN、±Inf、零/负非法值时拒绝。
- 所有中间量也要检查溢出/非有限：差分、四元数范数/归一化、平方/乘积、体积换算、立方容量、加法、比例映射和最终输出；不能仅检查最终字段。Python 任意精度整数不代表运行时浮点安全。
- 先完整校验和计算候选记录/尺寸，再一次性提交状态。非法输入或冲突事件必须导致无部分变更：记录、计数、序号水位、幂等索引和账本读数保持原样。若通过上游权威序号输入，拒绝不得消耗/自增本地“下一个号”。
- 建议纯宿主 oracle 以明确异常/错误结果区分 `INVALID_INPUT`、`IDENTITY_CONFLICT`、`STALE_OR_REVOKED`、`SNAPSHOT_INVALID`、`NUMERIC_OVERFLOW`；具体错误载体可由模块实现自选。拒绝不应伪装成成功或返回一个可被记账的部分结果。
- 尺寸上限可使呈现半径饱和，但账本确认量仍原样保留，并应可独立查询；不因封顶而丢掉后续收入。下游重置应从新确认账本状态重算，而非在旧显示尺寸上乘缩放比。

## 兼容与非目标

保留现有 `test_attachment.py` 的往返、独立物件scale、哈希差异、预算/合并兼容覆盖，以及 `test_size_model.py` 的立方关系、半径/直径类型、封顶、重置、有限输出和负输入覆盖。兼容测试通过不代表身份生命周期、数值全域、原子失败和独立 oracle 已充分覆盖。T51 旧草案中的本地序号和renderer排序/预算不作为应维持的语义；移除前应通过新测试替代相关覆盖。此处不定义 C# / Udon 具体容器、Unity API、渲染池策略或比赛账本实现。
