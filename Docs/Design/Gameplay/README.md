# 回合经济平衡模拟（离线，PROVISIONAL_NOT_TESTED）

**状态：`PROVISIONAL_NOT_TESTED`。** 本目录只有一个标准库 Python 离线模型、一个场景/敏感性 CLI 和它们的测试。它把 `Docs/config/prototype_defaults.json` 与 `Docs/Design/Maps/PicnicLawn/` 的原型数据代进一个可重复的回合经济里，用来找**敏感参数**和**结构矛盾**。它没有 Unity 场景、没有物理、没有网络、没有真人数据；任何数字都不能当作平衡、公平、性能或舒适度 PASS。

| 文件 | 内容 |
|---|---|
| [`round_model.py`](round_model.py) | 确定性回合模型：参数/状态/结果 dataclass、地图快照、`simulate_round(params, policy, map_spec, seed)`、三种策略 |
| [`simulate.py`](simulate.py) | 场景 sweep + ±20% 敏感性 + 时间去向；写 `reports/` 的 CSV 与 Markdown |
| [`tests/test_round_model.py`](tests/test_round_model.py) | 21 个 `unittest`：成长单调、交分缩小/最小门槛、轮换时刻、奖励层、被吞/重生、单槽、门槛、确定性、默认地图自洽 |
| [`reports/`](reports/round_report.md) | 本次实际运行的完整报告（`round_report.md` + 6 个 CSV，含交分规则对比） |

复现：

```bash
cd <repo root>
python3 -m unittest discover -s Docs/Design/Gameplay/tests -v
python3 Docs/Design/Gameplay/simulate.py --out Docs/Design/Gameplay/reports
```

默认 seed 7 打印单次对局；敏感性用 seed 1–5 取均值（模型对争夺顺序敏感，单 seed 差几个百分点不算趋势）。

## 1. 模型是什么、不是什么

**是：** 一个按 0.25 s 步进的回合经济近似。它知道每个区域还剩多少件、每件多大/值多少，知道球径门槛、球体积、交分缩小与最小兑换门槛、回合末奖励、被吞/重生、单槽道具和区域间的走路时间。它回答“在这些参数下，180 s 里谁在什么时候长到多大、交了多少、被吞几次、时间花在哪”。

**不是：**

- **不是物理**：没有扫掠、碰撞、坡度、凹凸、滚动角速度；移动是“区域到区域的距离 ÷ 速度”。
- **不是网络**：没有权威裁决、延迟、预测回滚、物品争抢窗口；区域库存是单机共享池。
- **不是真人技术**：策略是三条固定规则（贪吃 / 避战 / 快交分），不是玩家。
- **不是原作数据**：数值来自本仓库 v0.3 原型文档。交分流程的**规则结构**已按原作公开证据改写（§2.4），但缩小公式、门槛数值、奖励类别仍是项目暂定，不是《Once Upon A KATAMARI》实测。
- **不是验收**：不证明可玩、公平、舒适或性能；对应门禁仍是 T21/T22/T27/T38/T39。

## 2. 模型规则与依据

### 2.1 吸收门槛（实际原型规则）

本项目的**道具**规则不是 PvP 的 1.35 比值。依据：

- [`PicnicLawn/README.md` §2](../Maps/PicnicLawn/README.md)：物件拾取门槛按档 s `0.08–0.30` / m `0.32–0.95` / l `1.00–1.95` m；§9 的尺寸门写“球径 < 1.05 m 挡死、≥ 1.25 m 可吸走长凳”。
- [`02_TECHNICAL_CONTRACTS.md` §1/§4](../../02_TECHNICAL_CONTRACTS.md)：`pickupDiameterWorldM` 是玩法门槛，不是 Mesh 包围盒；半径/直径/门槛分字段。
- Unity 运行时目前**没有**吸收实现（`Assets/VRC_Katamari/Runtime` 只有 `KatamariMath` 与 `GroundContactMath`），所以模型采用文档门槛，而不是猜一个运行时常量。

因此模型用：

```
可吸收 ⇔ 物件 pickupDiameterWorldM ≤ 球 collisionDiameter × absorb_size_ratio
```

`absorb_size_ratio` 原型值 `1.0`（即“球径 ≥ 物件门槛”，边界含等号）；1.35 只用于 PvP 吞噬（`swallow_diameter_ratio`）。花圃的 1.10 m **翻越**门是地形门，不在吸收规则里，模型不模拟（只影响路线，不影响本模型的区域距离）。

物件门槛取 `prop_catalog.csv` 的 `game_longest_dim_m` 再按档位夹到上表区间；长条例外：`collapsed_bench` 3.6 m 长，按 §9 取门槛 **1.25 m**（不是 3.6 m）。

### 2.2 体积 → 半径

`r = cbrt(3V/4π)`（等价于 `d = d0·(V/V0)^(1/3)`），`V = V0 + units × c`，`c` 由 `units_to_max_diameter` 标定：**吃满整张图的 1356 价值单位，球正好从 0.30 m 长到 2.20 m**。于是 t1(0.55)/t2(0.95)/t3(1.45)/满径分别约 18 / 106 / 388 / 1356 单位。`radius_exponent` 只是形状探针，1/3 是文档给的球等效映射；改成别的值等于放弃体积守恒，只用于看“成长曲线形状”有多敏感。

### 2.4 交分与回合末奖励（2026-11-14 按原作证据改写）

`Docs/Research/KatamariBallRules/README.md` §1 Q1/Q2 把原作的计分流程查清了，本模型据此改写：

| 规则 | 原作证据 | 本项目取值 | 状态 |
|---|---|---|---|
| 必须把球滚进场景内的「変換エリア」才计分 | [research §1 Q1](../../Research/KatamariBallRules/README.md)（Tier 1 制作人原话） | 核心区 + 4 锚点轮换，必须到台 | 已确认 |
| 交分＝用体积换分，球会**变小**（不是清零） | research §1 Q2 / C2（Tier 1「小さくなるのと引き換えに」） | 缩小公式见下 | 已确认（缩小）／公式为项目发明 |
| 球太小不能兑换 | research §1 Q2 / C4（Tier 2「小さい塊の場合はポイントをゲット出来ません」） | `min_bank_diameter_m = 0.55 m` | 已确认（有门槛）／数值为项目暂定 |
| 兑换区约每 **60 s** 换位 | research §1 Q1/Q3 / C3（Tier 2+3） | `bank_cycle_s = 60 s` | 强暗示 |
| 回合末 3 个类别各给第一名 **+50 pt** | research §1 Q1 / C11–C12（Tier 2） | 默认开启，3 类 | 已确认（结构）／类别与平局规则为项目选择 |
| 单局时长 | **unknown**（research C18） | 180 s | 项目暂定 |

缩小规则（`bank_residual_fraction = 0.25`，可调）：

```
post_bank_diameter = start_diameter
                   + (pre_bank_diameter - start_diameter) * bank_residual_fraction
（下限夹到 start_diameter；0.0 等价于旧的重置规则）
```

**这个公式是本项目发明的**：原作只说“变小”，没说按直径还是按体积、也没给比例。计分口径不变：`score += 本次新增未交存单位`。缩小后保留的那部分体积记为 `carried_units`，它**已经计过分**，所以不会进入下一次交分；起始球体积仍然永远不计分。因此“反复交分刷初始核心体积”不成立（测试覆盖）。

回合末奖励只发给**严格第一名**；平局该类别不发——这是项目选择，不是原作事实。1 人局不触发奖励（那只是测试构造，不是对局）。

## 3. 会让数字偏乐观/偏保守的地方（重要）

1. **区域清空偏乐观。** 模型里球停在区里直到“当前球径再也吃不到东西”，一次访问就清空该区。真实扫掠每次只能碰到一部分，所以**本模型的拾取总量是上限**；真实对局会剩更多资源。
2. **PvP 接触偏保守。** 只有两人在同一个区域才算接触；走廊擦身、抢同一件、跨区追击都不会触发吞噬。真实吞噬次数应该更高，尤其在交分台和毯子中心。
3. **区域距离偏乐观。** 直线 ×1.35，没有绕篱、门口拥堵、坡度；也没有“大球只能走 4 m 支路”的代价。
4. **没有补货（默认）。** 每局从 452 件开始；`restock_period_s=0` 对应 T22 尚未实现的状态。
5. **没有遮挡、没有视觉、没有网络。** 这些都影响真人拾取和 PvP，模型不覆盖。
6. **参数不是原作值。** 3 件/s、3 m/s、0.5 s 接触、25% 抢走、30 s 站点刷新都是本模型的建模假设，文档里没有对应数字。
7. **缩小公式是项目发明。** 原作只确认“交分会变小、且有最小兑换门槛”，没有给出比例或换算空间。`bank_residual_fraction=0.25` 是用户 2026-11-14 的暂定值，不是原作数值；它恰好让 0.55 m 的最小交分球缩到 0.3625 m（仍高于 m 档 0.32 m）。改这个值会同时改变分数节奏和后期硬度。

## 6. 结论（带数字）

1. **（a）2.20 m 仍然不可达，而且不是交分规则造成的。** 65 个玩家回合里 ≥2.20 m 是 **0/65**，最高峰值 1.49 m；≥1.45 m 有 35/65（43–105 s），所以 t3 档并不是完全装饰。结构性原因：1356 单位 = 一次满径，而“一次不中断的成长”必须在 180 s 内吃满约 1356 单位——完全不交分的单人上限也只有 1182 单位 / **2.10 m**，4 人分摊 1.57 m。**只改交分规则救不了 2.20；要改的是 `units_to_max_diameter` 或球径上限。**
2. **（b）交分后的软锁消失了，被吞后的软锁还在。** 缩小后球径最低是 `0.30+(0.55−0.30)×0.25 = 0.3625 m`，比 m 档门槛 0.32 m 高 4.25 cm；内置策略实际交分尺寸 0.46–0.60 m，更安全。后期（120–180 s）低于 0.32 m 的桶 **100% 来自被吞→重生**（four_mixed 30 个低桶：25 个重生后、5 个被吞瞬间；triple 30 个：15/15），没有一个是交分造成的。但 4 人局后期仍有 31% 的桶 <0.32 m（triple 42%、restock 9%、duel 0%）；末球径均值 0.43 m（范围 0.30–0.60），比旧规则的 0.31 m 好，但仍有 15/20 个玩家回合末球径 <0.55 m（多数是刚被吞或刚交分）。**下一步该动的是重生球径/s 档补货，而不是交分。**
3. **（c）缩小规则不涨总分，只改分布。** 同 60 s 轮换、关奖励：旧重置 1171 → 新缩小 1195（**+2.0%**）；回到旧的 45 s 轮换：1201 → 1193（**−0.7%**）。交分次数 4.0→5.0，末球径均值 0.31→0.43，被抢单位 43.4→29.0，但吸附总量 1316→1300 略降。**缩小让“交分”从一次性事件变成节奏循环，代价是少吸一点、多跑一点；它不会把总分推高。**
4. **（d）奖励层占 8.7–11.9%，把分差拉大 29%，但本次没翻盘。** four_mixed 奖励 140 分 = 总分的 **10.5%**，分差 314→404。5 个 seed 里 0 次翻盘：前两名交存分差只有 9–13 分，但两人通常各拿 1–2 个类别（例如 average_eater +100、fast_eater +50），净差被抵消或放大。**结构上 50 分足以翻盘**（单测里一个类别就能改写名次）；实际是否翻盘取决于类别相关性——最大球径/拾取件数往往和领先者同向，吞对手数则可能反向。若想稳定名次，应降低 `bonus_points` 或去掉与领先强相关的类别。
5. **（e）`min_bank_diameter_m = 0.55 m` 不高也不低，但余量不大。** 所有 65 个玩家回合都在 **12.8 s（12.2–13.8）** 内到 0.55 m，所以它不会拖慢开局。它的作用是保证“缩小后还能吃 m 档”：0.44 m 时缩小球只有 0.335 m（离 0.32 m 只剩 1.5 cm），后期 <0.32 m 的桶升到 44%、总分 1359；0.55 m 时余量 4.25 cm、后期低桶 31%、总分 1335；0.66 m 时低桶降到 25%、末球径 0.51 m，但交分次数 5→4、总分 1316。**0.55 是“不制造新软锁”的安全下限附近；若要更硬的后期，0.60–0.66 更合适，代价是少一次交分。**
6. **公平性第一杠杆仍是吞噬比，时间是“跑路”。** `swallow_diameter_ratio` −20% 分差 404→553、被吞 12.4→24.6；`base_speed` −20% 分差 493。4 人局 69% 的人在跑路、20% 在拾取，交分相关（bank_travel+bank_service）只占 5%。新参数（缩小比例/最小门槛/奖励分）单独 ±20% 都 ≤2%，**它们改的是节奏与后期硬度，不是总分或分差的主因**。

## 8. 已定规则与仍需要用户/主管拍板的参数

按影响从大到小：

1. **【已定，不再是开放项】交分后按比例缩小，不重置。** 用户 2026-11-14 拍板：`post_bank = start + (pre−start)×0.25`，下限 0.30 m；`min_bank_diameter_m=0.55`；轮换 60 s；回合末奖励默认开启。模型显示这样消除了“交分软锁”（缩小球 0.3625 m > 0.32 m），总分几乎不变（+2.0%），后期球径均值 0.31→0.43 m。**比例已定 0.25（用户 2026-11-14，PROVISIONAL）**：公式是项目发明，没有原作比例可对；0.20/0.30 只作敏感性对照（0.20 更接近重置、0.30 后期更硬），不再是待拍板选项。
2. **`units_to_max_diameter` / 价值表。** 1356 单位 = 一次满径，意味着 2.20 m 必须一次不中断吃满整张图；完全不交分的单人上限也只有 2.10 m。若希望 t3 是常规体验，需要把满径成本降到 ~600–800 单位，或把 `gainVolumeUnits` 整体上调。
3. **`swallow_diameter_ratio`。** 1.35 是公平性的第一杠杆（1.08 时分差 553 vs 404）。这是“要不要允许滚雪球”的产品选择，不是纯数值问题。
4. **被吞后的软锁（重生 0.30 m + m 档 0.32 m 门槛）。** 交分侧已经安全（0.3625 m），但被吞仍回 0.30 m；s 档耗尽后这个 2 cm 间隙就是最后的软锁（后期 31–42% 的桶 <0.32 m 全部来自被吞）。应由用户决定“重生保底体积 / 重生球径 0.33+ m / 补 s 档 / 降低 m 档门槛”。
5. **补货预算与周期（T22）。** 当前 452 件是“一局一次性预算”；4 人局会吃干。需要用户给出“每区每 30 s 补多少、补哪些档”的目标。
6. **磁铁“强度”到底是什么。** 文档只给 4 s；模型用“吞吐 ×2”。若磁铁实际是“把可吸物件拉过来”，它的收益与遮挡/候选上限强相关，需要先定实现再定数值。
7. **火箭是否需要存在感。** 当前 1.5×/2.5 s、外环站点，模型里经济效果为 0；要么改位置/时长，要么接受它是“脱身工具”而不是“得分工具”。
8. **奖励层的类别与平局规则。** 原作确认“3 项第一名各 +50”，但类别清单只见到 5 个候选（吞球数/冲刺/道具/Brother/最大尺寸），且没写平局怎么办。本项目默认 `吞对手数 / 最大球径 / 拾取件数`、平局不发；若要“稳定可预测的名次”，应降低 `bonus_points` 或改用与领先弱相关的类别。
