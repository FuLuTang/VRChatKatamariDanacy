## 1. 现象与根因

### R33：盒门已接通，但球侧半径与事件时序仍错（2026-11-17）

证据：R33 的 Play 日志与两张截图。两图可见红芯周围若干件与芯有明显间隔；截图不能独自证明每件已挂载，也不能用核心网格当物理球尺。

1. **主因是门被放大，不是仅日志错字。** R33 的 `EvaluatePendingCandidates` 在 v2 打开时把 `collisionRadiusWorldM` 换成 `TryPickupReach`：`max(r·(|ûx|+|ûy|+|ûz|), 针支撑)`，立方体角向最多 1.73r。电机打印 `boxDistance − reachRadius`，宿主打印 `boxDistance − 当前collisionRadius`；宿主没有使用视觉核心半径 0.111 m。旧电机 70/70 非正只证明碰到了放大的触发壳，不能证明碰到了物理等效球。首件还没有吸附件时已经 `reach=.1867125 m`，而起始物理球半径约 `.111 m`。
2. **按 id 配对全部 70 对**：电机 gap 中位 −8.65 mm；宿主 69/70 正（唯一 −9.2 mm），范围 −9.2～117.5 mm；宿主减电机的差中位 **77.2 mm**。三日志分别 33 / 25 / 12 对，最后一份延续第二份。题述“宿主全正/+87 上限”并非完整原始日志统计。
3. **可直接量化的 36 对**（宿主之后到下一条 story 之间无吸收）：用 story 的 `diameter/2` 作为吸收后物理半径，分解 `Δgap = 1000·(reach − r_after) + ΔboxDistance`。29/36 的 `ΔboxDistance` 绝对值 ≤0.2 mm，5/36 为 0.35～1.15 mm，2/36 为 **36.90 / 42.78 mm**；半径项累计解释这 36 对总差的 **97.0%**，几何残差中位约 −0.006 mm。其余 34 对没有足够紧邻半径日志，**不外推分摊**。story 直径保留四位小数、gap 一位小数，分解约有 0.125 mm 舍入误差。
4. **例子**：`r33_play3.log` 55–59 行，牙膏电机 gap −3.4 mm、reach .2684886 m，宿主 +109.7 mm，story D=.311 m；半径项 112.99 mm，余量约 +0.11 mm。`r33_play.log` 100–102 行的风铃余量 +36.90 mm、`r33_play2.log` 92–94 行 +42.78 mm 则证明确有几何漂移，不能只改日志。
5. **时序缺陷独立成立**：电机自己的 `Update` 累加器一次可跑多步（不是 Unity `FixedUpdate`）；阶段 5 判门 → 6 提交事件 → 7 成长 → 7.5 推出 → 8 更新滚转 → 最后应用显示，宿主另一个 `Update` 才消费环。旧环仅存 id/道具位置，宿主用消费时球心和滚转算 local。漂移可来自同一步成长推出或后续步，方向可内陷也可悬外。旧日志没有接触球心/步号，**不能把 36.9/42.8 mm 说成若干完整 8 cm 步**；4 m/s×.02 s=.08 m 只是上限量级。现行实现见 §3.1，新增步延迟与中心位移分开记录。

**B：红芯可见**是另一个显示机制问题，核心随碰撞直径更新/针覆盖的决定见 §3.2/§3.4；下列为改造前对照，不是 R33 当前核心尺寸：

**B 的量化 (读图 + 离线模拟)。** 所有者今天的图（球径约 0.28 m，目视 ~20 件）：红色像素约 1976 px，红色区域包围盒 61×72 px，按竖向直径估圆盘红可见约 49%，按横向估约 68%（遮挡使圆盘直径不确定，只当量级）。离线模拟（现状放置、随机朝向、就近吸收、真实 `growthMm3` 定价、3 个随机种子均值）吸 10/20/30 件时红可见 72% / 51% / 41%，量级与所有者的图一致。**起因不是“视觉球比碰撞球大”**（视觉球 0.95·r，不大于物理球）。

## 3. 现行设计

### 3.0 可吸收性与挡路

**owner 2026-11-17：还不能吸的道具挡住球。** 接触碰撞与吸收体积门分开：门尚未放行的实体仍是障碍，不能因它是道具就允许球穿过；碰撞代理按道具形状，视觉球芯不参与判定。本条记录现行决定，不声称新的运行时验收。

### 3.1 吸附位置：触发即接触，原地冻结

- **触发 = 道具自身有向盒到球心的最短距离 ≤ 碰撞半径 + contactRadius（默认 0）**，v1/v2 完全同一口径；不读视觉核心，不把立方体方向支撑半径或滚动针壳传入吸收门。采用等效球而非推断的原作 `Mh` 盒，是明确的工程取舍（原作盒形状/朝向未知，见 [`PARITY_AUDIT.md`](../../Parity/PARITY_AUDIT.md) 的“吸收触发的几何”行）。
- **冻结的是触发那一步的相对位姿，不是宿主消费事件时的位姿**：`PickupAbsorbStepMath.CommitAcceptedAbsorbs` 输出成功行后，`AttachmentStepMath.RecordAbsorbedEvent` 在成长前调用 `AttachmentMath.TryCaptureContactPose`，用阶段 5 的接触球心、上一球心/滚转和本步支撑法线，经同一份 `VisualRollMath` 算到接触点的滚转（使用吸收前半径），再经 `TryWorldPoseToLocal` 转出局部位置/朝向写入固定 16 槽事件环。只有账本提交成功才记事件；道具位置/旋转使用门实际判过的候选快照。之后的成长推出与任意 N 步运动只携带此局部位姿。
- `PickupFieldHost.AttachProp` 经 `AttachmentStepMath.TryReadAbsorbedEventAttachment` 只读取事件局部位姿、写入 `AttachmentRoot`，再经 `AttachmentStepMath.TryAttachRadialProxy` 登记相同局部位姿的径向代理；**不读消费时的自由道具世界位姿来重算，也不回退到当前球姿态**。保留原朝向、原尺寸，不加埋入偏移，不拉入，不径向重定位，允许互穿。
- **诊断一份实现**：两端 `boxGapMm` 都调用 `AttachmentMath.TryComputeBoxGap` → `PickupAbsorbMath.TryComputeContact`，定义为 `1000 × [boxDistance − (吸收时碰撞半径 + 吸收时contactRadius)]`。电机量世界接触位姿，宿主量实际写入的局部位姿（球心为零）；同一个球面在刚体变换下不变。通过 `event` 配对，两端差应 ≤0.2 mm，附着值应 ≤0（允许浮点/一位小数打印造成 ≤0.2 mm 正值；这不是门的玩法余量）。`delaySteps` 与 `centerDeltaMm` 单列，不掺进 gap。成长使当前物理球与显示核一起更贴近或包住旧件；接触诊断仍按吸收瞬间球面判断。
- **吸附瞬间的星爆特效**（原作约 0.07–0.13 s，接触点处）：记为**需求**，属以后的美术/特效项，本轮不做。

### 3.2 球芯显示尺寸：跟随当前碰撞直径

- **owner 2026-11-17：显示等体积直径 = 当前碰撞球直径**，开局蟹座 0.222 m；吸收、交分缩小或重置时直接更新，不设平滑弹簧。理由是消除贴碰撞球面的粘附件与显示核之间的空腔。
- 原作依据为 REROLL 玩家观察核会变大并吞入旧件，以及 Takahashi 2004 postmortem 的镜头随球变大拉远说法；证据强度：**玩家观察 + 开发者镜头说法**，不宣称严格同径是原作测量。专利 Mp/Mh/Mr 分离不推出固定核。
- `core_XX` 仍按关卡命名，是皮肤而非尺寸档；先用 core_01。归一化子节点尺度仍为 `1 / D_mesh`，父 CoreMesh 由 BallView 写当前碰撞直径；缺素材保留原球。参考素材及引用场景不提交或上传。见 [CORE_SKIN](../../BallPresentation/CORE_SKIN.md)。
- 不做粘附嵌入或外推；附件仍在触发那一步冻结，原尺寸不变。成长核可以逐渐包住旧件；凹凸表面与理想碰撞球面的局部差异由观感验收确认。

**现行实现**：`BallView.Update` 读 `2 * GetCollisionRadiusWorldM()`，有效且变化时写 CoreMesh 尺度；`GetVisualCoreRadiusWorldM()` 返回当前碰撞半径。核心与诊断随成长更新，滚动根/附件根尺度不变。

### 3.3 埋没 / 消隐

**不做埋没隐藏。** 核随碰撞球成长时可包住旧件，但不据此修改体积、账本、已吸附表或径向代理；原作相对大小消隐仍与本项分开。

原作的相对大小显示层级（专利 d1–d3）**默认不做**，因为它会隐藏小件、让球更秃；只在 Quest 上已吸附渲染器数超预算时再启用，阈值没有原作数，届时单独测。

### 3.4 对碰撞 / 接地 / 径向针代理的影响（离线估算）

**吸收判定与接触 v2 不受本项影响**：核尺寸跟随只改视觉；碰撞、墙、台阶、爬升仍读 `r_phys`；吸收体积门读语义直径不变。

**接地视觉**是需要回答的问题：外轮廓约为等效直径的 1.15 倍时，道具会不会明显插进地面，径向针代理（16 向、cap `min(0.35·r, 0.30 m)`）能不能托住。离线估算（蟹座 432 件可吸件，nearest-first 吸收，真实 `growthMm3`；每件在盒刚触到物理球时放置并再陷入 0–2 cm（一个定步），朝向相对球随机（球滚动），3 个随机种子；吸到 D=0.30 / 0.50 / 0.80 m）：

| 量 | D=0.30 m | D=0.50 m | D=0.80 m |
|---|---|---|---|
| 已吸附件数 / `r_phys` | 24 / 0.150 m | 86 / 0.251 m | 192 / 0.400 m |
| 外轮廓半径 / `r_phys`（p10 · 中位 · p90，随机朝向球面方向） | 1.33 · 1.46 · 1.57 | 1.36 · 1.55 · 1.94 | 1.42 · 1.59 · 2.1–2.7 |
| 物件越过物理球的深度，即“插地”深度（中位 / p90 / 单种子最大，cm） | 6.9 / 8.7 / 11 | 13.7 / 23.6 / 27 | 24.5 / 61.5 / 94 |
| 针代理 cap `min(0.35 r, 0.30)`（cm） | 5.3 | 8.8 | 14 |
| 现规则下能进代理的长物件数（最长边 ≥ 0.5·D 且长宽比 ≥ 2.5） | 0 | 0 | 2 |
| 按现规则（≤4 个长物件）代理托住后的剩余插地（中位 / p90 / 最大，cm） | 6.9 / 8.6 / 11 | 14 / 23.7 / 27 | 22–27 / 44–70 / 63–94 |
| 假设代理收**全部**吸附件（16 向、cos 衰减、cap 同上）后的剩余插地（中位 / p90，cm） | 3.1 / 5.3 | 7.2 / 17.2 | 15.4 / 52.0 |
| 朝下方向上“整体离地”（轮廓小于 `r_phys`）的方向占比 | 0% | 0% | 0% |

读法：

2. **会明显插地，而且今天已经如此，与核显示缩放无关**：插地深度由“件在物理球外伸出多少”决定，与核心大小无关；今天的放置更靠外（reach 壳），只会更深。D=0.30 时中位 6.9 cm（约 0.46 r），D=0.50 时 13.7 cm，D=0.80 时 24.5 cm（中位）。
3. **现有径向针代理托不住**：它只登记 ≤4 个“长物件”（最长边 ≥ 0.5 倍核心直径、长宽比 ≥ 2.5），0.30/0.50 m 一件都没有、0.80 m 两件，对插地没有贡献；即使 cap 放开到收全部吸附件，0.30 m 能托一半（剩余 3 cm），0.50/0.80 m 仍剩 7/15 cm（p90 17/52 cm）——因为 cap 是 `0.35·r`，而我们的件相对球偏大。**所以接地视觉要靠原作那种“针模型覆盖所有吸附物”，不是靠现有 4 个长物件代理。**
4. **轮廓比原作大**：我们的外轮廓中位 1.46–1.59×`r_phys`，原作约 1.15（0.9–1.3）。差在件相对球更大（定价/内容，见 `/tmp/ball_audit/visual_report.md` 与 O6）；原作录像还见 30–60% 的嵌入（弱证据），我们按 Lead 决定触发即接触、不加嵌入，轮廓因此偏大、凸出更多。这不是缺陷判定，是 Unity 验收轮要看的量（U5、U6）。
5. 外轮廓 p90 在 0.80 m 到 2.1–2.7 倍，来自极少数大件（体积门允许至球体积的 10%，几十厘米的长件径向戳出）；这类件正是 `maxProxyProtrusionWorldM = 0.30` 与长物件代理设计的对象。

**对策（Lead 2026-11-17 已定，已实现）：针模型覆盖全部吸附件。** 每件吸附物把它的 8 个盒角点对 16 向针做增量 max 合并（约 128 次点积，无每帧成本），最远角点没越过核心 `minProxyProtrusionM`（1 cm）的件忽略；cap `min(0.35·r, 0.30 m)` 与 `maxProxyLiftPerStep` 暂不改，**PROVISIONAL**。v1 每步取 16 根针的针尖进接地求解，v2 把针尖当扫掠段进接触，`CompactNeedleCap` 因此升到 16。cap 后剩余插地的离线估算（与上表“全部吸附件”行同一模型，3 个种子均值）：D=0.30 / 0.50 / 0.80 m 为中位 3.1 / 7.2 / 15.4 cm，p90 5.3 / 17.2 / 52.0 cm，最大 7.8 / 21.6 / 72.2 cm；对比不收针时的 6.9 / 13.7 / 24.5 cm（中位）。是否放宽 cap 与抬升上限、会不会出现“被凸出物顶得颠”的手感，仍是所有者决定（O8），先看 U5。

## 8. 实现与剩余验收

接触几何唯一实现是 `PickupAbsorbMath.TryComputeContact`；两端诊断经 `AttachmentMath.TryComputeBoxGap`。候选判门、提交、队列压紧与尺寸重算入口在 `PickupAbsorbStepMath`；冻结位姿事件环与针登记入口在 `AttachmentStepMath`，供电机、宿主和离线工具共用。接触局部位姿经 `TryCaptureContactPose` 在成功提交同一步存入环。C# 与 Python 的球侧 pickup 半径都等于物理碰撞半径；无立方体支撑/针壳替换分支。核心跟随与全件针覆盖见 §3.2/§3.4，未为修复悬空调整 cap、成长、惯性或驱动。

剩余交给 Unity 操作员：编译 UdonSharp、运行新增纯值与 preview-scene 集成 NUnit、同路线重跑 U1/U2/U8 并观察全部 `event` 配对（含非零 delaySteps）、复核既有 U3–U9。未经这轮不得宣称截图、Unity 行为或 Udon 编译通过。
