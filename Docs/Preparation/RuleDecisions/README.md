# P09 规则与项目选择决策矩阵

**盘点日期：2026-10-11；2026-11-14 增补第二轮公开来源证据。** 本文区分可复核公开来源事实（官方文案／制作人采访／玩家实机报告）、公开资料未说明的 `unknown`、当前项目范围选择、待确认的项目原型参数。它不是T01最终验收、用户批准记录、原作完整规则、实现证据或T06接口冻结；不得从项目建议推断原作机制。

## 文件与证据层级

- [decisions.json](decisions.json)：每个主题分别记录已确认内容、unknown、项目选择/原型、候选选项及选择风险。
- 公开来源依据为 [T01参考规则矩阵](../../Research/ReferenceRules/rules_matrix.md) 所引Bandai Namco Europe FAQ（S02）、公告（S03），以及第二轮证据：4Gamer制作人石田遼专访（S04）、note.com玩家实机报告（S05）、Katamaripedia对战模式页（S06）、CGMagazine评测（S07）。核查过程与原话见 [KatamariBall规则公开来源核查](../../Research/KatamariBallRules/README.md) 的C1–C22。仅采用其明确表述：制作人采访属官方口径但只覆盖其答问范围；玩家实机报告与Tier 3 wiki一致时才交叉印证；不把宣传用语或推断外推到未写的具体PVP流程。
- 当前项目决定以 [00范围与事实边界](../../00_SCOPE_DECISIONS.md)、[02技术契约](../../02_TECHNICAL_CONTRACTS.md)、[01玩法草案](../../01_GAME_DESIGN.md) 为准；任务状态和依赖以仓库根 `tasks.json` 为准。
- 可选项是供用户/主管评估的候选，不是投票结果。`recommended_option`保持空值，`decision_owner`列为用户/主管或之后相应门禁负责者。

## 如何使用

1. 发布/冻结任何原作规则前，先看 evidence_status。`official_text_confirmed`／Tier 1 官方口径（含制作人采访）明示的有限事实才算确认；Tier 2 玩家实机与 Tier 3 wiki 只做交叉印证（`strongly implied`）；公开文档未回答即 `unknown`，不能用经验、旧作或AI推断补齐。
2. 对 unknown，可先按项目已明确方向构建可调方案；若项目规格尚未由用户/主管选择，维持待定，不将候选数值硬编码。
3. 每一选择列出单位与证据边界：几何长度用共享世界米，分数/收益使用各自账本单位，时间用秒；无已知值时写`unknown`，不填零或伪装实测。
4. 任何需参考游戏实机的新结论，需要获准、可复核的版本/模式/步骤/录像时间点。任何项目体验阈值需先由用户/主管确定，然后用对应真人/多人门禁验证。
5. 项目首发目标仍是两图；一图方案只是待批准的范围变更，见 [P17 RFC比较](../../Archive/Preparation/ReleaseRFC/comparison.md)。本目录不修改根任务或任务状态。

## 关键未决

T01与第二轮研究已确认的原作规则主干：KatamariBall为4人对战；计分必须把球送进场景内的交分区（「変換エリア」／玩家称「ポイントエリア」；在王子飞船正下方、约每60秒换位并显示导航图标属 Tier 2/3 强暗示），交分是**用体积换分、球会变小**（不是回到初始球），球太小不给分；被更大的球撞到会被吞、短暂不能动并在别处重生，**没有淘汰**，同尺寸弹开、可吞更小的对手；对战有宝箱道具（变大或妨碍对手）与加分Brother；结算另有3个项目各给第一名+50pt。仍然 `unknown` 的是：单局时长、回合数、体积→积分换算公式与最小兑换体积数值、对战道具完整清单与数值、地图数量/出生点/补给。项目已有的「交分后回到初始体积」、单槽磁铁/火箭、KO等待与保护、180秒与45秒轮换等是项目设计方向或原型值，不是对原作细节的认证；交分缩小规则、最小兑换门槛、轮换周期与是否采用结算奖励层已列入 [OPEN_DECISIONS](../../OPEN_DECISIONS.md)。详见JSON并在接口冻结前由主管审阅。
