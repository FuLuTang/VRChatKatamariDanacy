## 1. 共同测量规则

- 全程使用单一共享地图世界坐标系，长度单位米（m），面积平方米（m²），时间秒（s），价值使用确认的 `gainVolumeUnits` / `bankedScore` 等游戏账本单位。禁止把本地视图缩放或Avatar尺寸用作玩法测量基准。
- **游戏碰撞直径**：从正式玩法判定使用的 `collisionRadiusWorldM` 计算 `collision_diameter_world_m = 2 × collisionRadiusWorldM`。这是通行/阻塞检查的主判据。
- **外观Mesh尺寸**：只是渲染包围尺寸/视觉包围范围，不等于碰撞直径、成长尺寸或拾取门槛。记录在独立的 `visual_mesh_*` 字段，仅供美术遮挡/可读性分析。
- **可拾取门槛**：物品的 `pickupDiameterWorldM` 是球能否拾取该ItemDefinition的玩法门槛，不应由Mesh bounds推算，也不应与球碰撞直径混为一个字段。
- 收益采用有权威来源的物件价值账本字段（例如 `gainVolumeUnits`）；不按Mesh数量、面数、包围盒体积或物件个数代替收益。`bankedScore`只作为交分后的确认分数记录。
- 先记录地图版本/build、配置/规则版本、仪器/采样方法、路径起终点和测试条件；每条数字需可复测。CSV中的空测量字段留空；不能用0代替未知。离线草案中可填 `unknown` 表示所需数据或规则尚无来源。
- 测量的是当前构建的实际结果，不应把设计图/预览渲染/灰盒设想当作游戏内实测。证据需记录版本、参与人数、球状态/碰撞直径、重复次数、日志/截图位置与未测项；真人与四客户端门禁仍按G4/T39执行。

## 2. 出生区公平：`spawn_fairness.csv`

每张图分别记录四个出生区（Zone A–D）；不要将名称预填为实际工程对象ID。每一行是一项“出生区 + 条件/重复”。建议同样的初始球状态、起始时钟、玩家输入方案和路线测量方法；轮换出生位置与玩家/控制方式，避免把玩家熟练度归因于地图。

推荐比较项：

- 初始尺寸可达资源的**确认收益总量**：只汇总路径可达、初始可拾取、账本 `gainVolumeUnits`，注明采样半径/允许路线和快照时刻。
- 从出生点到第一个资源带、中央交分锚点及两条主要出口的实际可走路线长度（m）；记录起终点定义和是否有坡道/障碍绕行。
- 达到下一个成长尺寸带的预期累计收益与实测收集时间。成长阈值和可拾取门槛需来自本项目有效配置/契约；在未冻结或未实测时填 `unknown`，不可借用临时默认值宣称通过。
- 补货前后低阶资源供给、补货等待/生成预告/可达性，以及重生时附近可达收益。

可用于分析的归一化描述（不指定通过阈值）：

- 四区收益相对均值偏差：`100 × (zone_gain - mean(all_zone_gain)) / mean(all_zone_gain)`；均值为0时标记无法计算，不填0%。
- 四区收益跨度：`max(zone_gain) - min(zone_gain)`，并可报告跨度/均值；单位和值来源必须一致。
- 路程相对偏差：`100 × (zone_route_length - mean(route_lengths)) / mean(route_lengths)`。不同目标的路线必须分组比较。
- 成长时间偏差：相同规则/输入方法重复轮换测量；报告原始值与分布，不用单局平均掩盖长尾。

是否采用相对收益/路程容差、玩家数、重复数、统计方式与软锁判定，均**待用户/主管在实际试玩前确认**。本模板不设固定公平百分比或上线阈值。不得只凭收益数字认定体验公平；需结合多局真人排名变化、重生可玩性和追逐循环。

## 3. 双出口、主路、交分与成长脱困：`route_checks.csv`

每行对应地图版本中的一个可复测检查点/测试用例。按每个出生区检查至少两条彼此独立可用的出路；记录路径/地标ID和实际路线。针对最大球使用当前有效的游戏碰撞直径，不使用可见Mesh直径。若最大球尺寸/碰撞口径尚未确定，字段填 `unknown`，不得把 prototype_defaults 写成已定最大值。

- 出口/主路：沿通行截面测量**最窄处净宽**（m），注明测量位置、高度/坡度/门槛、碰撞代理与测量工具。可计算 `clearance_margin_m = min_clear_width_m - ball_collision_diameter_world_m`；该值仅为几何差额，不自动等于安全可通行，须实机通过并检查转弯/扫掠/侧向余量。
- 交分路径：记录当前bank anchor版本/位置、可达性、入口选择、到达路线、是否能被单球堵死，以及交分后重置对路线/资源循环的影响。锚点轮换方式未知时标记 unknown；不要假定原作周期。
- 成长脱困：分别记录进入窄区前后碰撞直径、所在位置、能否原路退出/使用备选出口、尝试时间、是否需要跳跃/强制传送/改变地图状态、最终结果。目标是必经路径不依赖跳跃，且成长后能安全脱困；实际判定方法与容差待用户/主管确认。
- 可视Mesh宽度、覆盖/遮挡和材质边界可作为展示备注，但不能代替玩法Collider的净宽或碰撞测试。

建议场景覆盖野餐的平路/毯缘缓坡/餐盘区交汇、玩具房书本缓坡/门洞感瓶颈/收纳交分点等**场景类型**；这仅为检查分类，不是已制作关卡或保证存在的结构。两主题的路径选择、瓶颈和交分路线需要在真实布局中体现差异，再由可玩性测试判断是否够明显。

## 4. 低阶资源和补货：`resources.csv`

每一行记录一个区域、低阶资源类型/批次及采样时间。每个ItemDefinition分别记录：稳定ID、尺寸拾取门槛（玩法字段）、账本收益值、`spawnGeneration`、资源状态/数量、补货触发/计划、确认生成时间、预告时间、初始可达性和重复拾取情况。不能把同一ID不同世代当成同一实例，也不能让旧请求领取新世代。

推荐指标：

- 低阶可达供给收益：`sum(available reachable instances' confirmed gainVolumeUnits)`。记录搜索范围/路线与采样时刻；统计不把预测收益计入。
- 区域耗尽比例：`(初始可达收益 - 当前可达收益) / 初始可达收益`，分母为0时记不可计算。
- 补货等待：`confirmed_spawn_time - depletion_or_trigger_time`；记录开始/结束定义及生成预告。计划值与实测值分栏。
- 重生可达量：玩家重生时，从重生点按当前球碰撞/拾取状态可达到的低阶确认收益；不只数生成物件数量。

补货公平容差、触发策略、延迟与生成预告要求均需主管/用户结合地图与多人实测决定，表中不预先指定数值。必须检查不会在球内生成奖励、不会推开玩家、不会导致资源复制，且收益价值守恒。
