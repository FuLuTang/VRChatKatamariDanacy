## 必须修正/补证

### T51 附着记录

1. 当前 `AttachmentLedger.attach()` 在本地分配 `_next_sequence` 并立刻递增；该序号不是权威稳定确认序号，跨端不同事件顺序会得到不同身份。改为接收确认事件的稳定 ID/权威序号，不自增冒充权威身份。
2. 缺少重复事件幂等、身份冲突检测、撤销（含撤销后重放）、跨局隔离/清理、完整快照原子重建及乱序/陈旧事件策略。
3. 当前输入校验不完整：位姿、四元数、scale、身份整数编码宽度、非有限分量均可能异常或生成非法状态。失败原子性需明确：验证/推导失败前后记录与索引逐项相等。
4. T51 不负责 renderer budget、排名、回收或 core-merge 生命周期。现代码把 `_enforce_renderer_budget` 和 `visual_state` 放在账本内部，与 T56 所有权冲突；兼容现有测试后应将这部分责任切出，而不是继续扩张。
5. 不变量：同一有效身份重复 apply 不增加记录；同 ID 不同负载报冲突；撤销精确记录；旧局/世代记录不可被新作用域误重放；快照验证失败不替换旧状态；位姿 round-trip 保持刚体关系和物件自身尺度。

### T52 尺寸

1. 当前公式先做 `volume_units * cubic_meters_per_volume_unit`、`base + confirmed`、`max_radius ** 3` 等中间运算。极大但有限的输入/参数可能溢出成 Inf 或抛 `OverflowError`；必须对每个中间量安全检查，且任何失败均无状态副作用。
2. 现有类型名区分核心半径、碰撞半径、语义直径，但跨接口仍须保持单位和语义，不允许半径误作直径；增加显式半径→直径的独立 oracle 检查。
3. `effective_volume_units = min(base + confirmed, cap_volume)` 是视觉尺寸映射的有效量，不是权威账本余额。尺寸封顶不得改写确认收益或 ledger；验证可通过在两笔不同大额确认输入下证明显示半径饱和而账本读数仍分别保留。
4. 基线、换算系数、半径上限、碰撞比及语义直径比均保持显式参数；不引入未经 T06/体验批准的默认常数。`cap < baseline` 应拒绝，不得悄悄缩小基线。

## 独立 oracle 测试策略（标准库 Python）

测试必须依据数学/状态不变量构造预期值，不重复调用生产函数推导期望。

### 附着

- 用独立旋转矩阵（按约定先写明矩阵方向）和手算点变换，构造随机但可复现的单位四元数样本；比对 world→local→world 的位置、旋转及球移动后的重建。添加 +Z 前向、绕世界 Y 正角方向和非零平移的具名案例，避免仅用同一四元数乘法实现作 oracle。
- 用两种不同消息到达顺序输入同一批**权威确认身份**，比较按身份排序的记录集合/哈希，而非要求序号本地连续；重复事件二次投递不改变记录数、值或水位。
- 冲突身份/不同负载、撤销、撤销后重放、跨局新代际、旧局事件、乱序事件、完整快照重建和快照分块版本不一致分别覆盖。失败前后对状态快照深比较，验证原子性。
- 保留原测试覆盖，同时显式说明预算测试是旧兼容行为，不作为 T51 最终职责的通过证据。

### 尺寸

- 从独立球体几何关系检查 `V = 4πr³/3`，使用比值而非调用被测反函数；体积扩大 8 倍半径扩大 2 倍。
- 测试半径与直径值差恰为 2；碰撞半径和 semanticDiameter 不得接受为 core radius 参数。
- 参数/确认量覆盖 NaN、±Inf、负数、bool、极大有限 float、中间乘积/立方/加和溢出、cap 小于 baseline、恰好在 cap、略超 cap；记录每个分支的预期明确拒绝或饱和输出。
- 维护单独的测试账本哑对象/原值；尺寸推导及封顶不能改变确认量，reset 结果严格来自新输入，不读取旧显示半径。
