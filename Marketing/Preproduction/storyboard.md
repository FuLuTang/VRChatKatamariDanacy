# T03 文字分镜（概念 vs 待实机）

> 仅文字拍摄/插画构思，不是成片、UI稿或实机证据。所有“概念”画面须标注为概念插画/示意；凡涉及真实操作、玩家数、功能、设备兼容、性能的画面，必须等待可玩构建与授权拍摄。不能用概念图冒充游戏截图。

## 画面 A：双手推球

1. **构图**：中近景，画面边缘可见参赛者的双手与两枚简洁虚拟推杆示意；前方滚球正朝一片散落的小物前进。私人 Avatar 只作为参赛者存在，不变形成甲虫。
2. **动作节奏**：先展示双手活动，再切到球改变方向、开始滚动；镜头保持稳定，不随球滚转。
3. **画面标签**：**[概念示意／待实机验证]**。推杆造型、实际输入映射、镜头反馈均未定稿。
4. **实机条件**：要宣称双手输入确实可用，须有已通过平台实验的构建和用户授权录制；不可先画成已实现功能。

## 画面 B：交分存分

1. **构图**：俯斜广角，滚球沿侧路驶向一个醒目的回收/交分锚点；远处显示仍可继续搜集的路线。画面用简洁图形表达“本局未交存资源 → 已存积分”，不仿制正式 HUD。
2. **动作节奏**：球进入锚点范围，物件/光点以抽象方式汇入记分标记；球体恢复小尺寸，接着玩家重新出发。
3. **画面标签**：**[概念示意／待实机验证]**。回收点外观、分数表现和球体重置效果是概念；确认的设计是仅将实际收集的资源转为本局安全积分，交分后球回到初始体积。
4. **实机条件**：事务、分数守恒、UI 与回合流程必须完成测试后，才能以实机镜头展示；概念动画不能作为验证。

## 画面 C：大球追逐

1. **构图**：宽幅低机位，两颗尺寸不同的滚球绕过日常物件，沿一条有分岔的路线追逐；甲虫吉祥物可在画外或角落做独立装饰，不使用第三方角色。
2. **动作节奏**：先有距离，再出现靠近与闪避；以位置和轮廓让威胁关系可读，不只靠颜色，不展示夸张撞击或摄像机抖动。
3. **画面标签**：**[概念示意／待实机验证]**。不同球径的相对关系和路线风险为创意表达；实际吞噬门槛、网络判定、移动表现均须测试，不在宣传中报出未经验证的数值。
4. **实机条件**：大球追逐、多人同步和碰撞效果必须来自真实可玩构建；参与者影像/Avatar/语音录制先征得同意。

## 画面 D：KO 与重生

1. **构图**：对手球靠近后，被吞角色以简短、非惊悚的图形提示“KO”；切到安全的短暂淡出，再回到较远的重生位置，出现轻量保护提示。
2. **动作节奏**：提示 → 短暂转场 → 回到赛场边缘 → 继续寻找小型资源。避免长时间黑屏、强制摄像机跟随敌球或令人误认永久淘汰。
3. **画面标签**：**[概念示意／待实机验证]**。约 3 秒重生与约 2 秒保护是设计草案参数，并未实测；不将秒数写入公开宣传。
4. **实机条件**：KO/重生事务、保护期限制、安全出生点及镜头稳定须由实际测试确认，未测前只可作为清楚标注的概念。

## 制作备注

- 现阶段交付是文字分镜；不创建图像、封面、UI、SVG 或高保真视觉。
- 成片方向应突出“推着走、卷入日常小物、冒险与存分的选择、追逐后仍可回来”，不使用原作名称、角色、标志或音频。
- 概念画面与真实游戏画面需在版面和标识上明确区分；正式宣传还需许可核查与用户批准。
